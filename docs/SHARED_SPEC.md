# LanguageTraining 共通仕様書

**版:** 1.0  
**対象:**  
- ネイティブアプリ（macOS / iPhone・本リポジトリ）  
- Web アプリ（Linux サーバ＋ブラウザクライアント・**別リポジトリ**）  

本ドキュメントは両製品で揃える**機能・データ・学習ロジック・AI 出力**の正本とする。  
UI の見た目や OS 固有の操作はプラットフォーム差分として許容する。データと振る舞いの意味は揃える。

---

## 1. 製品概要

### 1.1 目的

英語の語句・文を学習カード化し、説明生成・発音音声・タグ分類・間隔反復学習を行う。

### 1.2 想定学習者（検証済みプロファイル）

- 日本語話者の成人が英語を学ぶ用途を第一とする  
- 目安: CEFR A2、外資系などで実務英語を使う意向  
- 学校向け・児童向けのトーンにしない  

### 1.3 検証済みの使い方

- 原文: 英語  
- 説明言語: 日本語（構造化 JSON 説明）  

その他の説明言語・非英語原文は UI／プロンプト上は存在するが、共通仕様上は「未検証オプション」とする。

## 2. プラットフォーム

| 製品 | 実行環境 | クライアント |
|------|----------|--------------|
| ネイティブ | macOS / iOS | SwiftUI アプリ |
| Web | Linux（推奨: Ubuntu 24.04 LTS on Proxmox VM）+ リバースプロキシ | Mac / iPhone / Android のブラウザ（**Safari / WebKit 優先**） |

### 2.1 Web 推奨インフラ（参考）

- ゲスト: Ubuntu 24.04 LTS（VM）  
- 配布: Docker Compose  
- HTTPS: Caddy または nginx + Let’s Encrypt（iPhone Safari では HTTPS 必須想定）  
- API: サーバ側のみが OpenAI に接続（API キーをブラウザに出さない）  

### 2.2 Safari 適合（Web 必須要件）

- レイアウトは WebKit（Safari 16+ 相当）で破綻しないこと  
- `100vh` 問題・セーフエリア・ソフトキーボードで入力欄が隠れないこと  
- タッチ操作で Explain / Library / Study が完結すること  
- 最新だけの Web API に依存しない（必要ならフォールバック）

## 3. 画面構成（共通）

両製品は次の 4 領域を持つ。

| 領域 | 役割 |
|------|------|
| **Explain** | 原文入力 → 説明生成 →（任意）TTS → カード保存 |
| **Library** | カード一覧・検索・タグフィルタ・詳細・タグ変更・削除 |
| **Study** | 双方向クイズ・間隔反復・統計ダッシュボード |
| **Settings** | API／モデル設定・タグ管理・インポート／エクスポート |

ネイティブ Mac は Settings を別ウィンドウ、iPhone / Web はタブまたは同等の設定画面でよい。

## 4. 機能仕様

### 4.1 Explain

| ID | 要件 |
|----|------|
| E-01 | 原文テキストを入力できる（貼り付け可） |
| E-02 | OpenAI Chat Completions で学習説明を生成する |
| E-03 | 説明言語が **Japanese** のとき、構造化 JSON（§6）を必須とし、セクション 1 の見出しは **「1. 日本語訳」**（「意味」ではない） |
| E-04 | 画面上、原文は先頭に 1 度だけ示す。説明本文に原文見出しを重複させない |
| E-05 | 生成後、カードをライブラリに保存できる |
| E-06 | 保存時にタグ（色付き）を選べる。未選択は未分類 |
| E-07 | 直近で選んだ保存タグを記憶し、次回の初期値にする |
| E-08 | 任意で OpenAI TTS により発音音声（mp3）を生成・カードに紐づけできる |
| E-09 | API 利用コストの概算を説明末尾（フッター）に付けてよい |

### 4.2 Library

| ID | 要件 |
|----|------|
| L-01 | 保存カードを新しい順などで一覧表示する |
| L-02 | テキスト検索（原文・説明）ができる |
| L-03 | タグで絞り込める: すべて / 特定タグ / 未分類 |
| L-04 | 行または詳細からタグ変更できる |
| L-05 | 詳細では説明を表示する（原文の二重表示を避ける） |
| L-06 | カード削除ができる |
| L-07 | 紐づく音声があれば再生できる |
| L-08 | タグの新規作成が Explain / Library / Settings のいずれかからできる |

### 4.3 Study

| ID | 要件 |
|----|------|
| S-01 | 学習可能なカードのみ出題する（§7.1） |
| S-02 | 方向: **日本語 → 英語＋発音** / **英語＋発音 → 日本語** |
| S-03 | 出題キューは間隔反復の優先度（§7.2）で構築する（既定上限 40） |
| S-04 | 自己採点: **Again** / **Good**（§7.3） |
| S-05 | 進捗・日次ログを永続化する |
| S-06 | 統計: 正答率・習熟・デッキ構成・直近 14 日の活動・連続学習日数など |

### 4.4 Settings

| ID | 要件 |
|----|------|
| C-01 | OpenAI API キーを保存できる（ネイティブ: Keychain / Web: サーバ秘密情報。ブラウザに平文永続化しない） |
| C-02 | モデル名・API Base URL・説明言語を設定できる |
| C-03 | タグ一覧の色変更・削除（削除時はカードの当該タグをクリア） |
| C-04 | ライブラリの ZIP エクスポート／インポート（§5.4）。インポート前に既存データのバックアップを取る |

### 4.5 ネイティブ固有（Web では同等代替）

| ネイティブ | Web での扱い |
|------------|--------------|
| iCloud Drive 共有フォルダ | サーバ上のユーザーデータ（単一ユーザーなら 1 ライブラリ） |
| Finder でデータフォルダを開く | エクスポート ZIP または管理 UI |
| macOS ウィンドウ位置・分割の復元 | ブラウザでは任意（必須ではない） |

## 5. データ仕様（両製品の同期・移行の正本）

### 5.1 ライブラリファイル

- ファイル名: `cards.json`  
- 現行フォーマット version: **`"2"`**（読込時は `"1"` も許容）  
- 日付: ISO-8601（小数秒あり可）  
- 文字コード: UTF-8  

正規スキーマの機械可読版: [`schema/cards.schema.json`](schema/cards.schema.json)

### 5.2 ルート構造

```json
{
  "version": "2",
  "tags": [ /* Tag */ ],
  "cards": [ /* Card */ ],
  "study": {
    "progress": [ /* Progress */ ],
    "days": [ /* DayLog */ ]
  }
}
```

### 5.3 各オブジェクト

#### Tag

| フィールド | 型 | 説明 |
|------------|-----|------|
| `id` | string (UUID) | タグ ID |
| `name` | string | 表示名（前後空白除去。空不可） |
| `color` | string | RGB hex 6 桁、`#` なし、大文字推奨（例 `2563EB`） |

組み込み初期タグ（新規空ライブラリ時）:

| name | color | 固定 UUID（推奨） |
|------|-------|-------------------|
| 仕事用 | `2563EB` | `A1111111-1111-4111-8111-111111111111` |
| 日常会話 | `16A34A` | `A2222222-2222-4222-8222-222222222222` |

未分類の表示ラベル: **「未分類」**（カード側は `category` 空文字）  
フィルタ「すべて」は UI 概念であり、データには保存しない。

推奨パレット:  
`2563EB`, `16A34A`, `DC2626`, `D97706`, `7C3AED`, `0891B2`, `DB2777`, `57534E`  
不正な色は `57534E` に正規化する。

#### Card

| フィールド | 型 | 説明 |
|------------|-----|------|
| `id` | string (UUID) | カード ID |
| `createdAt` | string (ISO-8601) | 作成日時 |
| `sourceText` | string | 原文（学習対象の英語など） |
| `markdown` | string | 表示・互換用マークダウン（構造化がある場合はそれから生成してよい） |
| `explanation` | object \| 省略 | 構造化説明（§6）。あればこちらを優先 |
| `audioFileName` | string \| null | 音声ファイル名のみ（パス禁止）。`*.mp3`、英数字と `-_.` のみ |
| `category` | string \| null/省略 | タグ名。空／省略は未分類 |

#### Study Progress

| フィールド | 型 | 説明 |
|------------|-----|------|
| `cardId` | string (UUID) | 対象カード |
| `easeFactor` | number | 既定 2.5、下限 1.3 |
| `intervalDays` | number | 日単位間隔 |
| `repetitions` | integer | 連続成功回数相当 |
| `nextReviewAt` | string (ISO-8601) | 次回復習時刻 |
| `lastReviewedAt` | string \| null | 最終復習 |
| `reviewCount` | integer | 総復習回数 |
| `correctCount` | integer | Good 回数 |
| `incorrectCount` | integer | Again 回数 |

#### Day Log

| フィールド | 型 | 説明 |
|------------|-----|------|
| `date` | string | ローカル暦日 `yyyy-MM-dd` |
| `reviews` | integer | その日の復習回数 |
| `correct` | integer | その日の正解数 |

### 5.4 ZIP アーカイブ（互換）

エクスポート ZIP は少なくとも次を含め、両製品で相互インポートできること。

```text
cards.json          # 必須（version 2 推奨）
audio/*.mp3         # 参照される音声（任意）
```

レガシー `cards.xml` はネイティブ移行用。Web 新規実装は **JSON のみ必須**でよいが、ネイティブが出力する JSON を読めること。

### 5.5 音声ファイル

- 実体はライブラリと同じデータ領域の `audio/` 配下  
- カードはファイル名のみ保持（ディレクトリトラバーサル禁止）

## 6. 構造化説明（CardExplanation）

説明言語が Japanese のときの正本。JSON フィールド名は英語、値の説明文は日本語（構造・語彙の英語チャンクを除く）。

### 6.1 オブジェクト

```text
explanation
├── translation: { japanese, naturalEnglish, usage, formality }
├── pronunciation: { stress, tips }
├── structure: { kind, parts, pattern }
├── grammar: { tense, articles, prepositions, other, why }
├── vocabulary: [ { english, gloss, collocations } ]
├── examples: [ { sentence, meaning } ]
├── notes: { similar, mistakes }
├── summary: [ string ]
└── costFooter: string?   # 表示用。API 応答には含めないことが多い
```

### 6.2 表示用マークダウン（互換レンダリング）

構造化データから生成する見出し順は固定:

1. **1. 日本語訳**（旧「意味」は表示時に日本語訳へ読み替え）  
2. **2. 発音**  
3. **3. 構造**  
4. **4. 文法**  
5. **5. 語彙**  
6. **6. 例文**  
7. **7. 注意点**  
8. **8. 要点**  

フィールドラベル（例）:

- 自然な日本語訳 / 自然な英語（学習用） / どんなときに使う / カジュアル / フォーマル  
- 強く読む音 / 発音のコツ  
- 種類 / パーツごと / 同じ型で言えるパターン  
- 時制・形 / 冠詞 / 前置詞 / この文に出るほかの文法 / なぜこの形なのか  
- 語彙: `**English** = 日本語 / collocations`  
- 例文 n / 意味  
- 似た表現との違い / やりがちなミス  

### 6.3 OpenAI 応答（Japanese）

- `response_format: json_object`  
- スキーマは §6.1（`costFooter` なし）  
- temperature 目安: `0.2`  
- プロンプト方針: 意味優先、短文、実務・成人日常、構造は SOURCE 英語順のチャンク、ストレスは大文字、該当なしは理由付き  

説明言語が Japanese 以外のときはマークダウンテンプレート出力（ネイティブ既存）。Web 初版は Japanese 構造化を優先実装してよい。

### 6.4 TTS（任意）

- 既定モデル例: `gpt-4o-mini-tts`  
- 既定ボイス例: `marin`  
- 学習者向けに明瞭・ややゆっくり

## 7. Study ロジック

### 7.1 学習可能条件

次を両方満たすカードのみ Study 対象:

1. `sourceText` が非空  
2. 日本語訳が取れる（`explanation.translation.japanese` 優先。なければ markdown から「自然な日本語訳」等を抽出）  

### 7.2 キュー優先度

低いスコアほど先に出す（実装はネイティブ `StudyScheduler` と同等）:

- 期限超過日数・ease の低さ・誤答率・未学習ボーナス  
- 翌日以降にスケジュールされたカードは大きく後回し  
- わずかな乱数ジッターで順序固定を避ける  
- 既定 `limit = 40`  

### 7.3 採点更新（SM-2 簡易）

| 操作 | 効果 |
|------|------|
| **Again** | incorrect++、repetitions=0、intervalDays=0、ease-=0.2（下限 1.3）、`nextReviewAt ≈ now+10分` |
| **Good** | correct++。repetitions 0→間隔 1 日、1→3 日、以降 `interval * ease`。ease+=0.05（上限 3.0） |

### 7.4 デッキ区分（統計用）

| 区分 | 条件 |
|------|------|
| New | 未復習（progress なし or reviewCount=0） |
| Due / Overdue | 復習済みかつ `nextReviewAt <= now` かつ未マスター |
| Learning | 上記以外の未マスター |
| Mastered | `repetitions >= 3` かつ `intervalDays >= 21` |

連続日数: ローカル日付で復習があった日を連続カウント。当日ゼロなら昨日起点を許容。

## 9. 非機能・セキュリティ

| ID | 要件 |
|----|------|
| N-01 | OpenAI API キーをリポジトリ・クライアント公開領域に置かない |
| N-02 | Web はサーバ経由で API 呼び出し（キーはサーバのみ） |
| N-03 | 音声ファイル名のパストラバーサルを拒否する |
| N-04 | ライブラリ読込失敗時、既存データを上書き保存しない |
| N-05 | インポート前にバックアップを残す |

---

## 10. 互換性ポリシー

1. **`cards.json` version 2 + ZIP** を両製品の交換フォーマットとする。  
2. フィールドの追加は後方互換（未知フィールドは無視して読めること）。  
3. 破壊的変更時は `version` を上げ、本仕様書と `schema/cards.schema.json` を同時更新する。  
4. 機能追加は「ネイティブ → 仕様更新 → Web」または逆順でよいが、**仕様書更新をマージの前提**とする。

## 11. Web 初版スコープ（推奨）

必須: E-01〜E-07, L-01〜L-08, S-01〜S-06, C-01〜C-04, Japanese 構造化説明, `cards.json` 互換, Safari 基本適合。  
任意（後回し可）: 多言語説明テンプレート、XML レガシー、ウィンドウレイアウト復元、マルチテナント認証。
